# MCP-интерфейс Notes Service (ЛР5)

Спецификация пограничного слоя между ИИ-клиентом (вероятностная система) и данными Notes Service (детерминированная система) по протоколу [Model Context Protocol](https://modelcontextprotocol.io), редакция 2025-11-25. В первом семестре выполняется только проектирование, код не разрабатывается. Решение зафиксировано в [ADR-006](../architecture/ADR-006-mcp-adapter.md).

| [resources.json](resources.json) | 3 шаблона URI и 2 статических ресурса |
| [traceability.md](traceability.md) | матрица трассируемости требований и сверка с моделью данных |
| [data-registry.md](data-registry.md) | реестр конфиденциальных данных и правила раскрытия |

## Принципы

- MCP-сервер – входной адаптер модульного монолита наравне с REST API. Он вызывает прикладные сервисы контекстов и не читает таблицы напрямую, поэтому инварианты N1–N5 действуют и для ИИ.
- Пользователь определяется только по токену (`sub`); ни один инструмент не принимает `user_id`.
- Схема – одновременно контракт и валидатор. Во всех объектах `additionalProperties: false`; ограничения не мягче столбцов БД; `format` дополнен шаблонами `pattern`.
- Учтена вероятностная природа модели: неразрушающий `append_to_note`, обязательная `expected_version` для замены текста, запрет замены текста заметки длиннее 50 000 символов, `idempotency_key` для каждого изменения.
- Выходные схемы – белый список полей (DTO): ответ проверяется по `outputSchema` перед отправкой.

## Инструменты

| Инструмент | Назначение | Область доступа | Характер изменения | Идемпотентность |
|---|---|---|---|---|
| `search_notes` | поиск по тексту, тегу и времени изменения | notes.read | чтение | да |
| `get_note` | полный текст, версия, теги, вложения | notes.read | чтение | да |
| `list_note_versions` | история версий без текста | notes.read | чтение | да |
| `create_note` | создание заметки | notes.write | добавление | по ключу |
| `append_to_note` | добавление текста в конец | notes.write | добавление | по ключу |
| `update_note` | замена заголовка и (или) текста | notes.write | разрушающее | по ключу |
| `set_note_tags` | установка набора тегов | notes.write | разрушающее | да |
| `delete_note` | мягкое удаление | notes.write | разрушающее | по ключу |
| `restore_note_version` | возврат к прежней версии | notes.write | разрушающее | по ключу |

Не включены: регистрация, вход и токены, загрузка файлов, протокол подтверждения синхронизации – это операции пользователя и его устройств. Массовых операций нет.

## Ресурсы

| URI | Семантика |
|---|---|
| `notes://{note_id}` | текущее состояние заметки; подписка на изменения через события outbox |
| `notes://{note_id}/versions/{version}` | неизменяемый снимок версии |
| `attachments://{attachment_id}` | метаданные вложения без файла |
| `tags://me` | справочник тегов пользователя |
| `sync://devices` | состояние синхронизации устройств (метка вместо названия устройства) |

Заметки, версии и вложения не перечисляются в `resources/list`, чтобы их нельзя было выгрузить в контекст модели одним действием.

## Доступ

Клиент получает токен по OAuth 2.1 у Identity & Access; токен MCP содержит `aud` MCP-сервера и `scope`. При подключении запрашивается только `notes.read`. Первый изменяющий вызов отклоняется ответом HTTP 403 с `WWW-Authenticate` и областью `notes.write`, после чего клиент запрашивает согласие пользователя. Токены REST API MCP-сервером не принимаются.

## Ошибки

| Уровень | Коды | Способ передачи |
|---|---|---|
| Протокол | −32700, −32600, −32601, −32603 | объект `error` JSON-RPC 2.0 |
| Схема и бизнес-правила | −32602 | результат `tools/call` с `isError: true` и объектом ошибки (`code`, `domain_code`, `field`, `rule_id`, `message`) |

Доменные коды: `SCHEMA_VIOLATION`, `NOT_FOUND` (в том числе для чужой заметки), `VERSION_CONFLICT`, `NOTE_DELETED`, `NOTHING_TO_UPDATE`, `CONTENT_TOO_LARGE`, `IDEMPOTENCY_KEY_REUSED`, `INVALID_CURSOR`, `TAG_LIMIT_EXCEEDED`, `INTERNAL`. Имена таблиц, SQL и трассировки стека в ответ не попадают.
