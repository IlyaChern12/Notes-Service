# ADR-006: MCP-адаптер для ИИ-клиентов

## Статус

Предложено (ЛР5, этап проектирования).

## Дата

29.10.2026

## Контекст

Пользователь хочет работать с заметками через ИИ-ассистента. Модель вероятностна: может выдумать идентификатор, передать неверный тип, переписать длинный текст с пропусками, выполнить инструкцию, внедрённую в текст заметки. База данных требует строгой целостности. Подключение выполняется по протоколу MCP.

## Рассмотренные варианты

1. Отдельный MCP-сервис с прямым доступом к БД – отклонён: появляется второй владелец данных в обход инвариантов агрегатов (ADR-002).
2. MCP-сервер как клиент собственного REST API – отклонён: двойная сериализация и копирование правил авторизации без выигрыша.
3. **MCP-адаптер внутри Backend Application** – принят.

## Решение

1. MCP – входной адаптер модульного монолита (Streamable HTTP), вызывающий прикладные сервисы Notes, Attachments и Synchronization. Инварианты N1–N5, история версий и outbox общие с REST.
2. Identity & Access выступает сервером авторизации OAuth 2.1; MCP-сервер – защищённым ресурсом (метаданные по RFC 9728). Токен MCP содержит `aud` MCP-сервера и `scope` (`notes.read`, `notes.write`); токены REST не принимаются и не передаются дальше.
3. Набор из 9 инструментов и 5 ресурсов: [docs/mcp](../mcp/README.md). Пользователь берётся только из токена.
4. Изменения ассистента помечаются `note_versions.changed_via = 'mcp'`, `device_id = NULL`; устройства получают их событием NoteUpdated.
5. Ошибки протокола – объект `error` JSON-RPC; нарушения схемы и бизнес-правил – результат с `isError: true` и кодом −32602 внутри, чтобы модель могла исправить вызов.
6. Изменения модели данных: `changed_via`, `UNIQUE (user_id, lower(name))` для тегов, полнотекстовый индекс.

## Последствия

Положительные:

- ИИ не может обойти правила, действующие для устройств;
- правки ассистента видны в истории и обратимы;
- отдельное согласие на изменение данных.

Отрицательные:

- Identity & Access должен поддерживать OAuth 2.1 и отдельную аудиторию токенов;
- нужны аудит вызовов и ограничения частоты (разделы безопасности ЛР5).
